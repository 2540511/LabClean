# LabClean · 实验数据清洗机

面向实验数据的**纯本地**清洗与可视化工具。Excel / CSV 拖进浏览器就地处理，**数据不上传、无网络请求、源文件只读**。

> 当前版本 v0.1：骨架 + 完整闭环（导入 → 体检 → 清洗 → 导出 → 图表）。

---

## 快速开始

```bash
npm install            # 安装依赖
npm run dev            # 开发模式，打开 http://127.0.0.1:5173
npm run build          # 生产构建，产物在 dist/
npm run serve          # 零依赖静态服务器，预览 dist（默认 127.0.0.1:5173）
npm run smoke          # 数据引擎自测（81 项断言，不依赖浏览器）
npm run sample         # 重新生成 samples/实验数据示例.xlsx（5002 行，两个工作表）
```

打开后可以点**「载入示例数据」**，或直接访问：

- `http://127.0.0.1:5173/?demo=1` —— 载入 3 个质量不同的示例数据源
- `http://127.0.0.1:5173/?demo=1&auto=1` —— 自动给第一个数据源跑三步清洗（演示/自检用）
- `http://127.0.0.1:5173/?demo=1&view=compare` —— 直接打开数据对比视图

也可以把 `samples/实验数据示例.xlsx` 拖进页面，走完整的真实导入链路。

> 注意：构建依赖 esbuild 启动子进程，在某些受限沙箱环境里会报 `spawn EPERM`，在普通终端里没有这个问题。

## 已经实现

| 模块 | 内容 |
|---|---|
| 导入 | `.xlsx` / `.xls` / `.csv` / `.tsv`；多工作表自动识别并切换；编码自动判定（UTF-8 / UTF-8 BOM / GB18030） |
| 解析 | 自写 RFC4180 CSV 解析（引号、内嵌换行、CRLF）；全部字段先按字符串读入，**不会被 JS 精度吃掉身份证/订单号** |
| 体检 | 类型推断（数值/文本/日期/布尔）、缺失、唯一值、重复行、稳健异常值（中位数 + MAD）、0–100 质量分、逐列问题清单 |
| 表格 | 虚拟滚动（百万行只渲染可见的几十行）、空值与异常值高亮、列宽自适应 |
| 图表 | 分布直方图（异常值单独成柱，不压扁坐标轴）、观测点散点 + 中位数/均值参考线、各列缺失率 Top 12 |
| 清洗 | 清理首尾空格、删除全空行、删除重复行、缺失值填充（中位数/均值/众数/0/文本）、文本转数字 |
| 撤销 | 全部清洗动作可**撤销 / 重做**（`Ctrl+Z` / `Ctrl+Shift+Z`），从原始数据重放，任意步都能回退 |
| 对比 | 清洗前后指标对照（行数/空值/重复/异常/质量分 + 变化量），被改动的单元格在表里**绿色高亮**，悬浮看原值 |
| 多源 | 一次导入多个文件 / 一个文件的多个工作表，每个数据源独立维护清洗历史；**数据对比**视图用质量卡片横向比缺失率/重复率/异常率 |
| 导出 | 单表：一个 xlsx 四个 sheet（数据/体检报告/摘要/日志）；多源：对比总表 + 每个数据源一张数据表 |
| 其他 | 步骤列表、还原到原始数据、拖拽导入、Web Worker 解析（界面不卡） |

  components/    界面组件（React）
  App.tsx        状态与流程编排
scripts/
  smoke.ts       核心逻辑断言（含真实 xlsx 往返、Worker 解析链路）

## 几个关键设计决策

**1. 为什么是浏览器而不是传统桌面软件**
免安装、跨平台、改一版全团队生效；而且「数据不出本机」是架构层面成立的，不是靠承诺——答辩时打开网络面板，全程零请求。

**2. 异常值用中位数 + MAD，不用均值 ± 3σ**
一个 999 就能把均值和标准差拉到失效。代码里用修正 Z 分数（阈值 3.5），MAD 为 0 时回退到 IQR。

**3. 直方图的分箱只覆盖正常区间**
否则一个极端值会把坐标轴拉长十倍，其余数据全挤成一根柱子。异常值单独归到两端的琥珀色柱子。

**4. 超过 16 位的整数一律按文本处理**
JS 数字只有 2^53 的安全范围，19 位的编号读成数字会被**悄悄改掉末位**。这是数据清洗工具最经典的事故。

**5. 撤销不存快照，而是「重放」**
清洗动作被描述成可序列化的步骤（`pipeline.ts` 里的 `OpSpec`），撤销 = 少重放一步。算子全部写时复制：只有真正改动过的行才复制新数组，其余保持原对象引用。所以原始数据永远不被破坏，内存开销只跟「改了多少」成正比，而不是跟表有多大都成正比。

**6. 解析和体检都在 Web Worker 里**
主线程只负责渲染，大文件也不会把界面卡成白屏。

## 下一步（按优先级）

1. **模糊去重**（编辑距离、拼音、全半角）与更细的清洗规则
2. **规则模板**：把一套清洗步骤存下来，下次一键套用（步骤已经是可序列化的 `OpSpec`，存成 JSON 即可）
3. **大数据引擎**：接 DuckDB-WASM，替换现在的内存数组方案（>50 万行时）
4. **PII 脱敏**：手机号、身份证、邮箱、银行卡识别与一键掩码
5. **Tauri 打包**：`npm run tauri build` 出单文件 exe（需本机装 Rust 工具链）
6. 导出时附「清洗前后对比」sheet、对比视图支持排序/筛选

## 隐私说明

- 全部计算发生在本机浏览器内存中，无任何后端接口。
- 源文件只读，从不覆盖；导出一律另存新文件。
- 断网可用。
