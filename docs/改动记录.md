## 1. 识别「只有公式、没有计算结果」的表格（`de6715b`）

### 背景

用脚本或库（openpyxl 等）生成的 xlsx，往往**只写公式、不写缓存值**。Excel/WPS 打开时会自己算，但磁盘上的文件确实没有结果。

LabClean 是只读解析器，不执行公式，于是这类工作表被读成一整列空白，界面显示成「缺失率 50%、质量分 50、统计项全空」—— 看起来像统计功能坏了。

真实案例：一份 300 人成绩表，`统计汇总` 里 28 个 `=ROUND(AVERAGE(...),2)`、`各科平均分` 里 6 个公式，全部读成空。

### 改动

| 文件 | 改动 |
|---|---|
| `src/core/xlsx-io.ts` | 读取时开 `sheetStubs: true`（SheetJS 默认会把「只有公式没有值」的格子整个丢掉，开了才能看见 `t === 'z'` 的占位格）；新增导出函数 `countFormulaOnly()` 统计数量；`RawSheet` 增加 `formulaOnly` |
| `src/core/profile.ts` | `formulaOnly` 透传到 `meta.formulaOnly`，并在 `notes` 里追加一条提示 |
| `src/core/types.ts` | `DatasetMeta.formulaOnly?: number` |
| `src/workers/table.worker.ts` | 解析、切换工作表两条路径都传 `formulaOnly` |
| `src/App.tsx` + `src/styles.css` | KPI 下方新增提示条渲染 `meta.notes`（此前这些备注只写进导出 Excel，界面完全看不到） |
| `scripts/smoke.ts` | +4 项断言 |

### 效果

导入后在表格上方出现黄色提示：

> 这个工作表有 28 个单元格是公式，但文件里没有保存计算结果，读出来是空的 —— 用 Excel / WPS 打开后保存一次，再重新导入即可

### 注意

`sheetStubs` 会让空单元格变成占位格，但 `sheet_to_json` 仍把它们当作空值，**不会被误读成 0**（有断言守着）。

## 3. 行筛选与列操作（`05b563c`）

这是本次**唯一动了架构**的改动：原来管线假设「列固定不变」，而列操作会改变列集合。

### 3.1 新增的四种清洗动作

| 动作 | 语义 |
|---|---|
| **行筛选** | 按某一列 + 算子（大于 / 小于 / 等于 / 包含 / 不包含）保留符合条件的行 |
| **删除列** | 删掉指定列 |
| **调整列顺序** | 左移/右移一位 |
| **重命名列** | 改列名，不动数据 |

筛选的细节（都有断言覆盖）：

- 大于/小于：条件值是数字时按数值比较（`12,000` 也能识别）；条件值不是数字时按字符串序比较；**空值不保留**（否则空单元格会被当成空字符串混进来）
- 等于：能转成数字按数值相等，否则按文本相等
- 包含/不包含：按文本，忽略大小写

### 3.2 管线结构：`rows + origins` → `rows + origins + headers`

| 文件 | 改动 |
|---|---|
| `src/core/clean.ts` | 新增 `opFilterRows`、`opDropColumn`、`opMoveColumn`、`opRenameColumn` 与 `FILTER_LABEL` |
| `src/core/pipeline.ts` | `OpSpec` 增加 4 种步骤；新增 `TableState { rows, origins, headers }`，`StepOutcome` 带 `headers`；**`applySpec(rows, origins, columns, spec)` 改为 `applySpec(state, spec)`**；`replay` / `buildStepSequence` 一并维护并返回表头 |
| `src/core/profile.ts` | `rebuildDataset` 支持传入 `headers` |
| `src/lib/diff.ts` | 逐格对比按**列名**对齐原始列，删列/调序后不再错位误判 |
| `src/core/template.ts` | 模板支持这 4 种步骤；套用时用「模拟表头」推进，删列后的后续步骤下标不会偏 |
| `src/components/Inspector.tsx` | 新增「行筛选」面板（算子下拉 + 条件值，回车即执行）与「列操作」面板（重命名、左移/右移、删除该列） |
| `src/App.tsx` | 传递 headers；删列后选中列下标自动夹回范围；列结构变化时关闭「原值」悬浮提示 |
| `src/styles.css` | 输入框、整行按钮、危险色样式 |
| `scripts/smoke.ts` | +23 项断言 |

### 3.3 使用方式

选中某一列后，右栏会出现两个新面板：

- **行筛选**：选算子 → 填条件值 → 点「保留「age」大于「30」的行」或直接回车
- **列操作**：改列名点「重命名」；「左移一位 / 右移一位」调顺序；「删除「xxx」这一列」删除（**只剩一列时禁用**，避免出现零列数据集）

所有动作照旧进「清洗步骤」列表、可 `Ctrl+Z` 撤销、进「操作日志」并随报告导出，日志文案例如：

```
行筛选（年龄 大于 30）        按「年龄」大于「30」筛选，保留 128 行、删除 172 行
删除列（age）                 删除了列「age」，剩余 11 列
调整列顺序（城市）             把「城市」从第 3 列移到第 1 列
重命名列（age → 年龄）         把列「age」重命名为「年龄」
```

### 3.4 已知限制

- **「调整列顺序」按位置存**。把这套模板套到列顺序不同的表上时，目标是「第几列」而不是「跟在谁后面」，可能不是想要的效果。
- 列结构变化后「清洗前后对比」只比较仍存在的列；被删掉的列不再出现。

## 4. 导出下载加固（`f436eee`）

### 背景

用户反馈点「导出 Excel」没反应（甚至弹红色报错）。

### 排查过程

1. Node 里跑完整导出链路：生成的 xlsx 有效（zip 校验通过、四张 sheet 齐全）
2. 无头 Edge + CDP 真实点击：浏览器**收到了完整字节**（34759 B），但下载状态是 `canceled`，文件没落盘
3. 对照实验：4 种不同的 blob 下载写法（含 2 KB 普通 blob）全部被取消 → 说明该环境的落盘通道本身有问题，不能只凭它下结论

结论：内容生成没问题，问题在**触发保存**那一步。

### 改动

| 文件 | 改动 |
|---|---|
| `src/core/xlsx-io.ts` | `downloadBlob` 不再在 `a.click()` 后立刻 `a.remove()`（Chromium 会因此取消正在进行的 blob 下载），改为 10 秒后移除、object URL 60 秒后再释放；补 `msSaveOrOpenBlob` 老 Edge 分支；**返回 blob URL** 供上层兜底 |
| `src/App.tsx` | 导出成功后记录 `{url, name}`，右下角显示「已生成 xxx.xlsx · 没开始下载？手动保存」提示条 |
| `src/styles.css` | `.save-bar` 样式 |

### 效果

导出后右下角固定出现一条提示，带一个真实的下载链接。**直接点链接是最可靠的下载触发方式**，可以绕开浏览器的「自动下载拦截」「多文件下载限制」。

## 5. 导出报错可诊断 + 控制字符净化（`b4fa753`）

### 5.1 报错可复制

用真实文件（4 个工作表）在无头 Edge 里逐表导出、导出全部、删列后再导出，均未复现红色报错。于是把报错做成可复制的形态，下次能直接拿到原文。

- `src/App.tsx`：新增 `describeError()`，报错里带 `error.name` / `message` / 栈顶 3 行
- 红色提示条改为等宽换行显示，并新增 **「复制详情」** 按钮
- `src/styles.css`：`.err-text`（`pre-wrap`、限高可滚动）

### 5.2 控制字符会让 xlsx 损坏

Excel 的 XML 不允许 `0x00-0x08`、`0x0B`、`0x0C`、`0x0E-0x1F` 这些控制字符，数据里一旦混进去，生成的文件打开就提示「需要修复」。

`src/core/xlsx-io.ts` 在 `buildWorkbook` 里统一剔除（`cleanExportValue`），对所有 sheet 生效。

## 6. 接口变更清单（给后续开发者的迁移提示）

```ts
// pipeline.ts
export interface TableState { rows: CellValue[][]; origins: number[]; headers: string[] }
export interface StepOutcome extends TableState { affected: number; detail: string }
export function applySpec(state: TableState, spec: OpSpec): StepOutcome   // 旧签名：applySpec(rows, origins, columns, spec)

// OpSpec 新增四种
| { kind: 'filterRows'; colIndex: number; colName: string; op: FilterOp; value: string }
| { kind: 'dropColumn'; colIndex: number; colName: string }
| { kind: 'moveColumn'; from: number; to: number; colName: string }
| { kind: 'renameColumn'; colIndex: number; from: string; to: string }

// profile.ts
export function rebuildDataset(prev, rows, opts?: { elapsedMs?: number; headers?: string[] })

// types.ts
DatasetMeta.formulaOnly?: number

// report.ts
interface CompareItem { ...; logs?: OpLogEntry[] }
```

**改代码时记住三条**：

1. 原始数据（baseline）永不修改，算子写时复制 —— 撤销靠「从 baseline 少重放一步」。
2. 任何会改变列集合的动作，都必须同时更新 `headers`，否则后续按列下标的操作会错位。
3. `smoke.ts` 有 140 项断言，改核心逻辑前先跑一遍拿基线，改完再跑。
